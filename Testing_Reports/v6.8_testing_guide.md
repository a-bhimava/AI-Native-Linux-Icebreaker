# v6.8 testing guide — see the pipeline, not just test counts

Two dev-host scripts show what the v6.8 pipeline actually does — no
guest VM, no daemon boot, no ISO required. Both work on the Mac.

## 0. Environment (one time)

```bash
cd ~/Documents/Icebreaker/dual-brain
export ICEBREAKER_LIVE_GEMINI_KEY=<your gemini key>
export ICEBREAKER_LIVE_ANTHROPIC_KEY=<your anthropic key>   # optional
```

## 1. Stage probe — where is the pipeline broken?

```bash
python3 scripts/ib_debug_v68.py
```

Walks 10 stages in order (config → deps → LiteLLM → SessionStore →
plan schema → marker substitution → tier-0 registry → verifier gate →
AgentGraph compile → bridge). First failure stops the walk and prints
the exception.

**Expected output on green:**


## 2. Interactive runner — watch a real query fire

```bash
python3 scripts/ib_run_v68.py 'list /tmp'
```

Real QB (Gemini by default), stubbed PB and mcpd. Prints planner
output, risk tier per step, each mcpd call, and the final outcome.

### Simple query

```
─── query: 'list /tmp'  (backend=gemini) ───
  [config]      model=gemini-2.5-flash
  [planner]     raw QB output:
                {
                  "action": "fs.list",
                  "target": "/tmp",
                  "reason": "user_requested",
                  "risk_level": "low"
                }
  [risk]        action=fs.list  tier=0
  [mcpd]        step 1  tool=fs.list
                 target=/tmp
                 stdout='file1.txt  file2.txt  README.md'
  [responder]   outcome=executed  tier=0
  [summary]     mcpd fired 1 time(s)
```

### F-60 nav phrase (Task #150)

```bash
python3 scripts/ib_run_v68.py 'take me to /var/log'
```

Prompt-engineering pass makes QB map this to `fs.list /var/log`
instead of `system.unsupported`.

### F-62 compound intent (Task #148)

```bash
python3 scripts/ib_run_v68.py 'get network status and save the result to /tmp/notes.txt'
```

You'll see the planner return a `plan` wrapper with two steps, the
second one carrying `$STEP_0_STDOUT` in `content`. Risk classifier
rates step 1 tier 0 and step 2 tier 2, so the graph pauses at the HITL
gate before firing mcpd — proving INV-6 max-tier-wins is enforced.

### Compare providers

```bash
python3 scripts/ib_run_v68.py --backend anthropic 'list /tmp'
```

### REPL mode

```bash
python3 scripts/ib_run_v68.py                     # then type queries
```

## 3. Live pytest with `-s` — see per-provider execution

Only when you want to run the full offline+live matrix:

```bash
python3 -m pytest controller/tests/test_agent_graph_live.py -v -s --timeout=180
```

`-s` disables output capture so you see the tests as they hit each
provider. Currently: 5 pass (gemini + anthropic × [smoke, bridge,
plan]), 1 skip (openai — no key).

## What each script is FOR

| Script | Answers |
|---|---|
| `ib_debug_v68.py` | "did my last edit break an integration boundary?" — 10-second sanity check |
| `ib_run_v68.py` | "what does the QB actually emit for this query?" — see planner output, plan wrapper, marker resolution, tier classification |
| `test_agent_graph_live.py -v -s` | "does the whole thing work end-to-end for each provider?" — the CI-grade lock |

---

## When to run what

- After editing `agent_graph_nodes.py` / `plan_executor.py` / prompts:
  → `ib_debug_v68.py` (5s), then `ib_run_v68.py "<query>"` (~4s / query).
- Before committing a task:
  → full pytest `controller/tests/ -q` (offline, 45s).
- Before merging a task PR:
  → `test_agent_graph_live.py` with keys set (10s, ~$0.001 in tokens).
- Before v6.8 ISO tag:
  → same three, PLUS live UTM sweep of the built ISO (mandatory per plan).
