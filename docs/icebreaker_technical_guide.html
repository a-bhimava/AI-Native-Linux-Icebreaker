1. Executive Summary

Icebreaker is an AI-native Linux operating system designed to fundamentally shift server administration from rigid syntactic execution to intent-driven operation. By embedding Large Language Models (LLMs) natively into the OS orchestration layer, it allows administrators to declare state and execute system tasks via plain natural language.

However, granting an LLM root privileges while exposing it to untrusted external data creates the conditions for a catastrophic "Prompt Injection via Confused Deputy" attack. The defining innovation of Icebreaker is not simply that an AI controls the computer, but the zero-trust architectural isolation separating AI "perception" from AI "execution," bound rigidly by Linux kernel-enforced sandboxing.

2. Threat Model & Design Goals

Primary Adversary: An attacker controlling untrusted content ingested by the system (e.g., a hidden payload within a read file, an email, or tool output) attempting to induce privileged actions—such as data exfiltration, destructive writes, or sandbox escape—via indirect prompt injection.

Design Goal: Even if the adversary completely subverts the Perception Model via injected content, they must not gain the ability to cause arbitrary tool execution, exfiltrate raw data, or escape the kernel sandbox. The defense is an information-flow and capability architecture, utilizing the Linux kernel as the unyielding enforcement floor.

3. The Multi-Brain Architecture

The architecture relies on four tiers with a strict, one-directional trust gradient. No single component simultaneously possesses (a) exposure to untrusted text and (b) the capability to execute tools.

Untrusted input (user text, file contents, tool output) | v [ QUARANTINED BRAIN ] Perception model — NO tool access | Structured Intent Object (candidate JSON) v [ CONTROLLER ] Non-AI schema-validation -> risk-classification -> HITL gate | Stores intent, emits OPAQUE UUID + allowed tool v [ PRIVILEGED BRAIN ] Execution model — NO raw text, only UUID-referenced intent | Concrete MCP tool call (parameters re-validated) v [ mcpd ] Rust daemon — stdio JSON-RPC only, schema validation | Fork child; apply Landlock + seccomp-BPF BEFORE execve v [ LINUX KERNEL ] Mandatory Access Control (Final enforcement)

Role Separation

Component Role Structural Limitations
Quarantined Brain Perception Reads untrusted input. Emits a candidate JSON Intent. Structurally barred from execution capabilities.
Controller Mediation Non-AI Python referee. Validates intent schemas, strips metacharacters, assigns risk tiers, blocks via HITL.
Privileged Brain Execution Decision Formulates exact tool calls. Never sees raw input; only receives an opaque UUID reference.

4. Security Invariants (INV 1-8)

Eight hard invariants define the system's security contract. These are enforced rigidly in code and cannot be bypassed by prompt manipulation.

  • INV-1 Brain Isolation: The Quarantined Brain has zero tool connections. The Privileged Brain has zero access to raw user input. Only a structured Intent Object, reduced to an opaque UUID, crosses the boundary.
  • INV-2 Schema Enforcement: The Controller strictly rejects Intent Objects falling outside the JSON schema or containing shell metacharacters (; & | ` $ < >).
  • INV-3 Network Isolation: The mcpd execution daemon communicates exclusively over stdio. It opens zero TCP/UDP/UNIX listeners, removing network-based attack vectors.
  • INV-4 Parameter Validation: Every tool-call parameter is validated against a compiled-in JSON Schema prior to execution.
  • INV-5 Kernel Sandboxing: Landlock LSM and seccomp-BPF filters are applied to the child process before execve. The system fails closed (refuses to execute) if kernel support is missing.
  • INV-6 Copy-on-Write (COW): Destructive operations outside the user's home directory trigger a COW dry-run. The user must approve the exact diff via a Human-in-the-Loop (HITL) prompt featuring a forced 3-second lockout.
  • INV-7 Model Integrity: Cryptographic SHA-256 verification of model weights at startup against a signed manifest. Mismatches abort boot.
  • INV-8 Audit Integrity: An append-only (O_APPEND) audit log records every intent (including rejected ones). Models lack write access to this log.

5. Kernel-Level Confinement (mcpd)

The Model Context Protocol Daemon (mcpd) is a hardened Rust application responsible for executing privileged operations. It implements defense-in-depth across multiple layers:

Two-Layer Filesystem Defense (TOCTOU-Safe)

File operations are defended by two independent boundaries:

  1. Userspace Validation: Rejects NUL bytes, backslashes, non-absolute paths, and paths outside the whitelist (/proc, /sys, /tmp, /var/log, /etc, $HOME). Sensitive directories (.ssh, .aws) force the COW path.
  2. Kernel Resolution: Actual file access utilizes openat2 with RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS. The kernel enforces that the path cannot escape the intended root or traverse symbolic links, closing Time-of-Check to Time-of-Use (TOCTOU) vulnerabilities.

The seccomp filter installs a strict denylist (mount, reboot, ptrace, bpf, setuid, listen, accept) combined with PR_SET_NO_NEW_PRIVS. Attempting a restricted syscall results in immediate process termination via SIGSYS.

6. The 14-Step Controller Pipeline

The run_turn() pipeline dictates the end-to-end request lifecycle:

  1. Receive user text and any untrusted context.
  2. Quarantined Brain emits a candidate Intent Object using Grammar-Constrained Decoding.
  3. Controller schema-validates the Intent Object (rejects metacharacters/extra fields).
  4. Risk-classify into Tier 0-3 (symlinks resolved via realpath).
  5. If Tier 3 (destructive): Route to HITL gate (3s lockout, 30s timeout).
  6. Store validated intent; issue opaque UUID (TTL = 300s).
  7. Assemble Privileged Brain context: {intent_id, allowed_tool, tool_schema}.
  8. Privileged Brain emits concrete MCP tool call via Chain of Thought.
  9. Outbound auditor scans payload to prevent context leakage (fail-closed).
  10. mcpd re-validates parameters against compiled-in JSON Schema.
  11. mcpd forks child, applies Landlock + seccomp-BPF, mounts COW if required.
  12. Execute under kernel confinement; capture result.
  13. Optional Verification-Brain round-trip.
  14. Append atomic JSONL audit record; return summary to Quarantined Brain only.

7. ISO Build & CI/CD Pipeline (cx-distro)

Icebreaker avoids brittle wrappers like live-build in favor of an explicit, highly automated direct-assembly pipeline orchestrated by build_v2.sh.

Build Stages

  • Stages 0-3 (Compilation): Verifies model checksums, compiles mcpd (Rust), and llama-server (CMake) directly from source. Installs the Python Controller into an isolated virtual environment.
  • Stage 4 (Chroot Assembly): Stages the includes.chroot directory, configures GNOME/XFCE UI defaults, hardens systemd services (e.g. UMask=0117 for IPC sockets), and overlays the GGUF model weights.
  • Stage 5 (ISO Assembly):
    • debootstrap provisions the Ubuntu base system.
    • mksquashfs packages the highly optimized read-only root image. (Compression can be disabled natively for debugging).
    • xorriso -iso-level 3 packages the kernel, bootloaders (GRUB/ISOLINUX), and the squashfs container into the final, bootable hybrid .iso.
Iterative Build Requirement To optimize resources in live environments, the Quarantined Brain service (icebreaker-qbd.service) is deliberately excluded from the multi-user.target by default. Only the Privileged Brain loads during startup.
