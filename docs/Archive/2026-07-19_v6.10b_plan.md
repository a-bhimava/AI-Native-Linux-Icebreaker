## Anti-hide / F-51 markers

PR #34 didn't introduce new F-# runtime bugs — it fixed existing ones
(F-69) and added new features. No new markers needed in
`incremental/versions/v2.manifest`. Rationale:

- **F-69 fix** — already has a marker (`F69-rpa-on`) in v2.manifest
  from v6.10 P2. The extended BP-13 lockstep guard is a test-side
  discipline, not a runtime behavior — doesn't need a venv marker.
- **RPA S1-R3** — new feature code (`rpa_bridge/*`). Runtime tests
  cover the code exists; a venv marker adds no value beyond
  `python -c "import rpa_bridge.workflow_gen; assert hasattr(...)"`.
  Skip.
- **Deps (langgraph, tomli-w, pytest-asyncio)** — enforced by pip
  install itself (venv fails to import if missing). Skip.

## Rollback strategy

If v6.10b arm64 or amd64 fails a smoke gate check that v6.10 passed,
the regression is squarely PR #34's fault:

- Revert PR #34 on a branch: `git revert 502a28c`
- Rebuild as v6.10c
- File the specific gate failure as a new F-# entry in GROUND_TRUTH § 7
- BP-13 discipline: add the failing gate to CI so it catches pre-ISO
  next time
